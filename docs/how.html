01
做東西的方法

先做滑板車，不要先畫汽車設計圖

假設你最後想要一台汽車。有兩種做法，差別大到會決定這件事會不會成功。

✗ 大多數人直覺的做法
輪子不能用
車架不能用
引擎不能用
汽車終於能用

照零件順序做。問題是前面三步都沒有人能用，也收不到任何回饋——萬一做到一半沒時間了，你手上什麼都沒有。而且做到最後才發現「其實大家要的不是汽車」，前面全白做。

✓ 這套工具箱要你走的路
滑板車能用
腳踏車能用
機車能用
汽車能用

每一階段都是「真的能用、可以拿給同事用」的東西。第一版很陽春沒關係，重點是它會動、你能收到真實回饋，再決定下一步要不要繼續、往哪走。這就是 MVP（最小可用版本）的意思。

!

第一次體驗不好，之後就沒人要用了

同事第一次打開你的工具，如果卡卡的、看不懂、資料是錯的，他就不會有第二次。所以第一版寧可只做一件事，但那件事要做到好用。功能少不可怕，難用才可怕。

!

大家一開口就是完整版

問需求的時候，聽到的幾乎都是「汽車設計圖」——所有功能一次到位。你的工作是把它切開：這一版先做哪一塊？哪一塊可以之後再說？跟 Claude 說「先做最小可用版本」，它會幫你切。

!

腳踏車想升級成機車，往往要重做

如果你心裡的終點是汽車，第一版就要先講出來——不是先做出來，是先講。Claude 知道終點在哪，第一版的地基才不會蓋成之後得整個打掉。

!

很多需求其實只需要腳踏車

停下來想一次：這件事真的需要汽車嗎？公司裡大部分的小工具，一台好用的腳踏車就夠了，而且它兩週就能上線、沒人要維護一台生鏽的汽車。真的需要汽車的比你想的少很多。

02
五個名詞

模型、Agent、API、MCP、Skill

這五個詞你之後一定會聽到。用同一個廚房的比喻講一遍，就不會再混淆了。

模型Model
＝ 廚師的腦袋會的菜、懂的原理、判斷力。模型本身只會「想」跟「回答」，它不會自己動手。你在 Claude Code 裡換模型，就是換一顆腦袋——有的想得深但慢，有的反應快但淺。
AgentAgent
＝ 會自己動手的廚師本人腦袋加上手腳。它會自己打開檔案、寫東西、執行指令、看結果不對再改。你用的 Claude Code 就是 Agent——這就是為什麼它能真的把專案做出來，而不只是給你一段程式碼要你自己貼。
APIAPI
＝ 出餐窗口兩個軟體之間講話的窗口，有固定格式：你按規定遞單子進去，它按規定把東西遞出來。你的工具跟資料庫要資料、跟 Google 確認身分，走的都是 API。你不用懂細節，只要知道「軟體之間是這樣互相叫東西的」。
MCPModel Context Protocol
＝ 萬用轉接頭讓 Claude 能接上外面的服務——Slack、Notion、Google Drive、公司自己的系統。接上之後，你可以直接叫它「去看那份 Notion 文件」「把結果貼到 Slack」。沒接就沒有，接了它才看得到那些東西。
SkillSkill
＝ 寫好的食譜把一件事的標準步驟寫下來，之後每次都照著做、結果都一樣。你打的 /new-project、/check 就是 skill——它們不是模型「臨場發揮」，是有人先把流程寫好了。這個工具箱本身就是一包 skill。
03
模型與思考深度

什麼時候該換腦袋、什麼時候該讓它想久一點

兩個可以自己調的旋鈕。多數時候維持預設就好，但卡關的時候知道有這兩個旋鈕，會省下很多來回。

旋鈕怎麼調什麼時候調
換模型model /model 換一顆腦袋。強的模型理解複雜需求、處理棘手 bug 比較穩，但比較慢也比較貴；快的模型適合改字、調版面這種明確的小事。
思考深度effort /effort 同一顆腦袋，讓它想久一點再動手。需求很模糊、或它連續改了兩三次都沒改對的時候，調高通常有用。
不是越高越好。想得越久＝越慢、越貴。日常「照著做」的事情用預設最划算；真正值得調高的時機是：需求很模糊、它連續改錯、或這個決定之後很難回頭（例如資料表怎麼設計）。
04
組成

你的工具是由哪幾塊組成的

你會聽到一堆名字。其實就是開一家店會用到的幾樣東西，一個一個對起來就懂了。

你會聽到相當於它在做什麼
Claude Code幫你做事的師傅你講需求、它動手做。整套流程都在它裡面跑。
VS Code或終端機工作檯師傅工作的地方。VS Code 是「有畫面」的工作檯，終端機是「只有文字」的工作檯——兩個做的事完全一樣，看你習慣哪個。
git / GitHub存檔點與雲端備份每做完一段就存一個檔，改壞了可以退回去。GitHub 是把這些存檔放到雲端，換一台電腦也拿得到。
Supabase倉庫 ＋ 門禁資料存在這裡（誰請了假、庫存剩多少），誰能進來、誰能看哪些也是它在管。免費。
Cloudflare Pages店面地址給你一個網址，同事用瀏覽器就打得開。免費。
Node.js工作檯的電源很多開發工具要靠它才能跑。裝一次就好，之後你不會再碰到它。
這六樣裡面，你真正要自己動手的只有兩件事：去 Supabase 註冊一個免費專案、去 Cloudflare 拿一把鑰匙。其餘全部由 Claude 代勞，它會在需要你出手的時候停下來告訴你。
05
前端與後端

「前端」「後端」到底在講什麼

這兩個詞會一直出現。一句話講完，你就知道自己的工具能做到哪、哪些要找幫手。

前端 ＝ 你看得到、點得到的畫面

跑在使用者自己的瀏覽器裡：頁面、按鈕、表單、清單。使用者直接看到、直接操作的都是。

後端 ＝ 在雲端幫你跑事情、把關的那一層

使用者看不到也改不了：存資料、驗身分、照時間自動做事、保管祕密鑰匙。它在雲端 24 小時待命。

你的 MVP ＝ 前端（畫面）＋ 一套現成的倉庫和門禁（Supabase）。沒有一個「你自己的後端」在雲端待命——這不是缺陷，是刻意的：少一層要顧的東西，你才做得起來。下一段講這個界線會影響什麼。
06
能力範圍

做得到什麼、做不到什麼

先知道界線在哪，就不會做到一半才發現卡住。

做得到 —— 大多數內部小工具

  • 記錄、清單、搜尋、篩選、分頁
  • 新增／編輯／刪除資料
  • 公司 Google 帳號登入
  • 權限控管：誰能看、誰能改、誰能刪
  • 報表畫面、簡單的統計

做不到 —— 要「真正的後端」才好做

  • 定時自動執行：每天早上自動寄週報、到期自動提醒。要有東西在雲端照時間自己跑。
  • 要藏密鑰的串接：接金流、寄 email、呼叫別家服務。密鑰不能放在畫面裡，放了誰都看得到。
  • 大量背景運算：批次匯入匯出、處理圖片。
需要右邊那些怎麼辦？要「把現成平台接起來、自動跑流程」（含排程與通知）→ 用 n8n 那條路。真的要變成公司級的正式功能 → 找 IT，或讓你的工具畢業進母艦，那裡有完整的後端。
07
常見問題

你可能會想問

我完全不會寫程式，真的可以嗎？

可以。你要會的是「把你想要什麼講清楚」，這件事你比工程師強。程式由 Claude 寫、由它檢查，它還會用白話告訴你怎麼在畫面上驗收。你看不懂的東西不用假裝看得懂——直接問它「這在做什麼」。

要花錢嗎？

你會用到的服務都在免費額度內（Supabase、Cloudflare 的免費方案，內部小工具綽綽有餘）。要付費的是 Claude Code 本身，那個公司出。

會不會弄壞公司的系統？

碰不到。你的工具用的是你自己的資料庫和網址，跟公司正式系統完全分開。另外工具箱裝好後會自動啟動幾道護欄，擋掉危險操作——例如不小心要刪掉工作成果、或動到公司正式機的設定，它會直接擋下來並告訴你原因。

資料安全嗎？可以放真實客戶資料嗎？

只有公司 Google 帳號進得來，資料本身也有多層保護。但測試階段請只放假資料。真的要放真實客戶資料之前，先找 IT——他們會幫你把專案搬進公司帳號底下再開放。

我做的東西會不會哪天就不見了？

不會。它存在你自己的雲端倉庫裡。用久了、證明有價值，還可以申請「畢業」搬進公司的大系統長期使用。

做到一半卡住怎麼辦？

直接跟 Claude 說「我卡住了」，把畫面上看到的貼給它。真的需要人幫忙的時候（開通登入、接公司帳號、接第三方服務），它會告訴你去找 IT——那不是你做錯了，是那幾件事本來就需要權限。
