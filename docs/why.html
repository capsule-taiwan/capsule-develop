選一個起點

你想做哪一種？

「種子」就是一個現成的起點，對應一種常見需求。看你要做的是「一個新的小系統」，還是「把現有的工具串起來」。

🧰 什麼時候用它：你要做一個「有畫面、有資料、能登入」的小系統——記庫存、追客戶、內部表單、簡單的管理後台⋯這種。

你會用到什麼（需求 → 我們選了誰 → 其實還有別的）

① 需要一個「倉庫」放資料
資料總要有地方存、也要記誰登入過。我們用 Supabase（免費、好上手）。
同類服務還有 Firebase、PlanetScale、Neon⋯ 有興趣可以去研究；這個種子預設用 Supabase。
② 需要一個「地址」讓別人打得開
做好的東西要有個網址，別人用瀏覽器才進得來。我們用 Cloudflare Pages（免費）。
同類服務還有 Vercel、Netlify、GitHub Pages⋯ 也都可以；這個種子預設用 Cloudflare。
③ 需要一道「門禁」只讓公司人進
用公司 Google 帳號登入（限公司信箱），只有同事進得來、看得到資料。上線前請 IT 幫你開通。
④ 需要一位「工程師」幫你寫
就是 Claude Code。你講需求，它建骨架、寫功能、做檢查，全程用白話跟你說。

先講清楚

前端？後端？你的工具做得到什麼

兩個常聽到的詞，先用一句話講白，你就知道你的工具能做到哪、哪些要找幫手。

🖥️

前端 = 你看得到、點得到的畫面

跑在你自己瀏覽器裡的東西：頁面、按鈕、表單。使用者直接看到、直接操作的都是前端。

☁️

後端 = 雲端幫你「跑事情、把關」的伺服器

使用者看不到、也改不了的那一層：存資料、驗證身分、照時間自動做事、藏祕密鑰匙。它在雲端 24 小時待命。

你的膠囊 MVP = 前端（畫面）＋ 一個現成的「倉庫＋門禁」（Supabase）

✅ 做得到（大多數內部小工具）

  • 記錄、清單、搜尋、篩選、分頁
  • 登入（公司 Google）、權限（誰能看／改／刪）
  • 新增／編輯／刪除資料

⚠️ 種子沒給你、要「真正後端」才好做

  • ⏰ 定時排程：例如每天早上自動寄週報、自動提醒——要有東西在雲端「照時間自己跑」。
  • 🔑 需要藏密鑰的驗證／串接：接金流、寄 email、呼叫別家 API——密鑰不能放前端（放了誰都看得到）。
  • ⚙️ 背景大量運算：處理圖片、批次匯入匯出。
那這些怎麼辦？　想「把現成平台接起來、自動跑」（含排程、通知）→ 用 n8n 種子；真的要變公司級的正式功能 → 找 IT，或讓這個工具畢業進母艦（那裡有完整後端）。
常見疑問

你可能會問⋯

要花錢嗎？

你會用到的都是免費額度（Supabase、Cloudflare 的免費層，個人小專案綽綽有餘）。要付費的是 Claude Code 本身，那由公司出。

我的資料安全嗎？

只有公司 Google 帳號進得來，資料還有多層保護。而且測試階段請只放假資料，不要放真實客戶資料；真的要放真資料時，通知 IT 幫你搬進公司帳號。

我做的東西會不見嗎？

不會。它存在你自己的雲端倉庫裡；用久了、證明有價值，還能「畢業」搬進公司的大系統長期使用。

我完全不會寫程式，真的可以嗎？

可以。你只要會用中文描述你想要什麼，Claude 幫你寫、幫你檢查，還會用白話告訴你怎麼在畫面上驗收。

做到一半卡住怎麼辦？

直接跟 Claude 說就好。真的需要人幫忙（例如開通登入、接公司帳號、接第三方服務）時，它會告訴你去找 IT。
